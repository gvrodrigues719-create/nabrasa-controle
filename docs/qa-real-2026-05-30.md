## 3. BUG-02 (P0) — Janela delete→insert CORRIGIDA

**Commit de correção:** `b4a8c49` — "fix(count): implement P0 idempotency and diagnostic tool"

**Problema original:**  
O fluxo de sincronização usava `delete()` seguido de `insert()`. Havia uma janela de tempo onde a sessão ficava sem itens. Se o banco fosse consultado nessa janela (por outro operador, pelo admin, ou por uma finalização concorrente), os itens seriam perdidos.

**Correção aplicada (`src/app/actions/countAction.ts`, linha 399):**
```typescript
const { error: upsErr } = await supabase
  .from('count_session_items')
  .upsert(upserts, { onConflict: 'session_id,item_id' })
```

**Garantias da correção:**
- `upsert` com `onConflict: 'session_id,item_id'` — operação atômica, sem janela de inconsistência
- O `delete` em `countAction.ts` existe APENAS em `deleteCountSessionAction` (exclusão explícita de sessão), nunca no fluxo de sync
- Após o upsert, o código busca os itens salvos e valida a contagem antes de marcar `status = 'completed'`
- Se `savedCount === 0` ou `missingItems.length > 0`, retorna erro e NÃO finaliza

**Prova de código (QA-M09):**
```
[M09] upsert com onConflict: true
[M09] delete antes de insert no sync: false
PASS ✅
```
